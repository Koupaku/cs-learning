## 3. 训练 1 讲义（本次，30~40 分钟）

### 一句话人话解释

> `useEffect` = 给组件装个"闹钟"，对 React 说：**"重画完了之后，顺便帮我做这件事。"**
> 第二个参数（依赖数组）= 你**盯着谁**——盯着的人变了，闹钟才重新响。

### 为什么需要它（30 秒版）

组件函数会被 React **反复调用**（每次 state 变就重跑一遍）。所以联网、定时器这种"渲染之外的动作"不能直接写在函数体里——不然你每敲一个字就发一次网络请求。`useEffect` 就是用来**控制这些动作什么时候执行**的地方。

## 5. 上次课遗留的两个问题（我答，请对照看）

### Q1（`react-weather/src/components/TodoApp.jsx` 第 18 行注释）

> "这里 addTodo 传进来的数是 input？怎么和 input 联系上的？"

**答：`addTodo` 其实一个参数都没有**，它是"空手"函数：

```jsx
function addTodo() { ... }          // ← 括号里是空的，没人"传"东西给它
<button onClick={addTodo}>添加</button>   // ← 传的是【函数本身】，不是它的结果
```

那它凭什么能用到 `input`？因为 **`input` 是同一个组件里的 state 变量**，`addTodo` 定义在组件函数内部 →
**站在里面就能直接看见外面那层冰箱上的便利贴**，不需要别人递进来。

> 一句话记忆：**在组件里，state 像贴在冰箱上的便利贴——组件内任何函数抬头都能看见它，不用传参。**

对比一下你另一处写法，就明白"传参"和"读外层"的区别：

| 写法 | 谁给值 | 什么时候 |
|------|--------|----------|
| `addTodo` 里读 `input` | 不用给，自己抬头看 state | 读外层变量（闭包） |
| `toggleDone(todo.id)` | 调用时**当场递进去**一个 id | 传参 |

顺带解释你可能会问的：`onClick={addTodo}` 不加括号 = **把函数本身交出去**；React 点击时会替我们调用它，
还会塞一个"事件对象"进去（你没写参数，所以那个对象被忽略掉了，没关系）。

### Q2（`notes/08-展开与不可变性打样/index.js` 第 49 行的问句）

> "`id === 1` 的意思是 `id === true` 吗?"

**不是。** `===` 是"**相等比较**"，结果才是 `true` 或 `false`：

```js
1 === 1        // → true   （读作："1 等于 1 吗？"）
t.id === 1     // → true/false（"这条的 id 等于 1 吗？"）
```

`1` 只是一个**数字**，不是什么"真值"；它跟 `true` 没关系。

顺便记住两条易错点：
- `=` 是**赋值**（把右边塞给左边），`===` 才是**比较**——练习 04 的 `if (running = true)` 就是栽在这。
- 比较必须是"两个东西比"，`t.id === 1` 左边是变量、右边是数字，比的是**值**。

## 8. 训练 1 的五个疑问（逐条回答 · 详解见 `notes/18-React写法读法卡.md`）

### Q1「useEffect 箭头指向的、由 `{}` 包裹的函数，这个叫什么？」
→ 叫 **回调函数（callback function）**——"交给别人、等别人在合适时机替我调用"的函数。
交给 `useEffect` 的这个，专业叫 **副作用函数 / effect 回调**；交给 `setInterval` 的叫定时器回调；交给 `onClick` 的叫事件处理函数。
**共同点：你写好了不自己调，交给 API 去调**——这就是"回调"的含义。→ 读法卡 §3

### Q2「{A, B} 里 A 和 B 分别代表什么，要怎么引用？」
→ 那是我写的**签名占位**：`A` = 第一个位置 = **函数**，`B` = 第二个位置 = **数组**。
它们**不是变量名**：代码里直接写 `useEffect(() => {...}, [count])`，不需要给 A、B 起名，也没法在别处引用它们。
（类比 `addEventListener('click', fn)`：第一个位置填"事件名"，第二个位置填"函数"。）→ 读法卡 §2

### Q3「onChange 的读法？第一次出现的方法或函数都应该解释它」
→ **承诺生效**：以后新写法一律先给**读法卡**（括号填什么 / 箭头是什么 / 返回什么 / 怎么接）。
`onChange={(e) => setText(e.target.value)}` 逐段读法：
"**当这个输入框内容改变时**（onChange），**收到一个事件对象 e**（React 塞进来的），**把触发事件的元素（`e.target`，就是输入框自己）的当前内容（`.value`）写进 text 状态**"。→ 读法卡 §8

### Q4「为什么"拆掉 timer"没被执行？一个函数里有 2 个 `return`，和 `if` 是什么关系？」
→ **关键澄清：那两个 `return` 不属于"同一个函数里的两条出口"。**
- `if (!running) return` → 结束的是**这次 effect 执行**（提前收工，后面全不跑）
- `return () => {...}` → 是这次 effect 的**返回值**，返回**一个函数**，**交给 React 保管**，不是立刻执行

**类比**：装定时器时你顺手交给 React 一张"善后说明书"，React 拿着站旁边，**到该拆的时候才照做**。
"该拆"只有两种时刻：① `running` 变了（重装前先拆旧的）② 组件被移除。
所以现在看不到"拆掉 timer"，只是因为**还不到时候**——点"暂停"它立刻出现。→ 读法卡 §4

### Q5「能写成 `setTodos((prev) => ({...prev, {...}}))` 吗？」（TodoApp 第 18 行）
→ **不能，但方向完全正确**（想用函数式更新，这个直觉很准）。两个错：
1. `{ ...prev }` —— `prev` 是**数组**，摊进 `{}` 会变成**对象**（`{0:..,1:..}`），`map` 立刻崩
2. `{ ...prev, { id: ... } }` —— 对象里每一项必须是 **`键: 值`**，光秃秃一个 `{}` 是**语法错误**

**✅ 正确写法**：`setTodos((prev) => [...prev, { id: Date.now(), text: input, done: false }])`
**口诀：中括号 `[]` 造数组，大括号 `{}` 造对象——括号形状要跟"我要造什么"一致。**
（你写的圆括号 `({...})` 只在"箭头函数直接返回**对象**"时才需要。）→ 读法卡 §6

### Q6「`setSeconds` 可以直接更新 `seconds` 的值吗？」（`UseEffectDemoCopy.jsx` 第 90 行新注释）★

> 你问的其实是：`seconds` 就在眼前，为什么不能写 `setSeconds(seconds + 1)`，非要写成 `setSeconds((prev) => prev + 1)`？

**答：语法上完全可以写，但在这个定时器里，它会让时钟"卡在 1 不动"。**

原因正是你在零件 2 已经撞见过的**闭包旧值**：

- `setInterval` 的那个回调函数**只被创建了一次**（effect 只在 `running` 变化时才重跑）。
- 它"出生"那一轮，`seconds` 是 `0`。这个 `0` 被**焊死**在回调函数里了。
- 于是每一秒它都算 `0 + 1 = 1` → `setSeconds(1)` → 屏幕**永远显示 1**。

```jsx
setSeconds(seconds + 1)        // ❌ 永远 1（seconds 被闭包焊死在出生那一轮的 0）
setSeconds((prev) => prev + 1) // ✅ 1 → 2 → 3 → 4（React 把最新值喂给 prev）
```

**读法**（读法卡 §5）：`setSeconds((prev) => prev + 1)` 读作
"**setSeconds：（上一次的秒数）=> 上一次 + 1**"。
括号里给的不是**新值**，而是一个「**拿旧值算新值**」的函数——这是 React 给 setter 的特权，普通 JS 函数没有这待遇。

📌 **一句话记忆**："直接给新值"要用**你当场看得见的值**；"算着给"就用 `prev =>`。
定时器和 effect 里看到的变量多半是**旧的**，所以在这些地方一律用 `prev =>`。

> 🔎 **顺带一个反面对照**：把依赖数组写成 `[running, seconds]` 也能让时钟走起来——因为每秒 `seconds` 一变，effect 就拆掉旧定时器、重装一个新的。
> 但这是"每走一格就把闹钟砸了换个新的"，**浪费而且会漂移**（每次重装都要重新计时，越走越不准）。
> **依赖数组写谁，要问"我希望它什么时候重装"，不是"怎么写才能跑起来"。**

### Q7「其实已经执行了，但是只是存在 return 里，等点暂停的时候，直接返回 return 就被执行」（第 112 行新注释）

**你自己把 Q4 想明白了 90%！** 👏 只差一个词的精度——要把**两件事**分开：

| 动作 | 什么时候发生 | 到底发生了什么 |
|------|--------------|----------------|
| ① `return () => {...}` **这一行** | effect 每次跑完（`running` 变成 `true` 那一次） | ✅ **执行了**——执行的结果是"**造出一个函数，并把它交给 React 保管**" |
| ② 函数体里的 `clearInterval(timer)` | React 决定"该拆"的时候 | ⏳ 这时才**真正执行** |

所以你说"已经执行了"→ **对，但要说清是"`return` 这一行执行了"**（= 交出了说明书），
**不是"`clearInterval` 执行了"**（说明书上的字还没念）。

后半句"等点暂停的时候……就被执行"——**方向完全正确**，只要把主语换一下就更准：

> ❌ 不是"`return` 被执行了"
> ✅ 是"**`return` 交出去的那个函数，被 React 调用（执行）了**"

**为什么点"暂停"它就会执行？** 因为点暂停 → `setRunning(false)` → `running` 变了 →
**依赖数组里盯着的这个人一变，React 就必须先给上一次的副作用善后**，于是掏出说明书照着念 → `[零件4]拆掉timer` 打印。

⚠️ 关键结论：触发清理函数的**不是"点击"这个动作**，而是"**依赖数组里的人变了**"（或者组件被移除）。
点击只是**让 `running` 变了的那个原因**——这正是依赖数组为什么这么重要（读法卡 §4）。

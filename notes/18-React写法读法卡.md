## 1. `useState` 读法卡（第 3 课补课）

```jsx
const [count, setCount] = useState(0)
//    └─①─┘ └──②──┘   └──③──┘ └④┘
```

| 格 | 内容 |
|----|------|
| ② 括号里 | **初始值**（initialState）——只在**第一次**渲染时用得上，之后 React 记住的是更新后的值 |
| ③ 返回什么 | **一个数组**：`[当前的状态值, 更新这个状态的函数]`（长度固定 2，顺序固定） |
| ④ 怎么接住 | 用**数组解构** `[a, b] = ...`。**名字是你自己起的**——`setCount` 不是 React 规定的，只是社区约定"值 / set值" |
| ⑤ 读法 | "让 React 记住一个状态，初始 0；这一轮渲染里它叫 `count`；要改它，调 `setCount`" |
| ⑥ 区分 | **React 特有**：`useState` 这个函数本身、返回值含义、"每次渲染拿到的是这一轮的值"<br>**普通 JS**：`const`、解构赋值、数组 |
| ⑦ 易错 | ① **顺序不能反**（数组按**位置**取——这跟你学的"对象按名字取"正好相反！）<br>② 不能 `count = 5`，必须 `setCount(5)`<br>③ 组件重画时括号里的 `0` 不再起作用 |

## 2. `useEffect` 读法卡 ★（本次第一顺位）

```jsx
useEffect(() => { /* 顺便做的那件事 */ }, [依赖])
//        └────── 参数1 ──────┘   └─参数2─┘
```

| 位置 | 名字 | 填什么 | 必填？ |
|------|------|--------|--------|
| 参数 1 | **回调函数**（副作用函数 / effect 回调） | **一个函数**——"重画之后顺便做的那件事" | 必填 |
| 参数 2 | **依赖数组**（deps） | **一个数组**，里面写**变量名**（⚠️ 不是值！） | 可选（不写 = 每次渲染后都跑） |

**⑤ 一句中文读法**
> `useEffect(A, B)` → "React，**重画完了帮我执行 A**；**B 里的人变了**，才重新执行 A。"

**他问的"{A, B} 里 A 和 B 分别代表什么、怎么引用"** ——答题：
- `A` = 第一个位置的**函数**（你直接写成 `() => {...}`，不用起名）
- `B` = 第二个位置的**数组**（你直接写成 `[]` 或 `[city]`）
- **它们不是你能在别处引用的变量名**，只是"第几个位置"的占位叫法。就像 `addEventListener('click', fn)` 里的两个位置：事件名 和 函数。
- 唯一"从 A 里出来"的东西：**A 可以 `return` 一个清理函数**（见卡 4）。

**⑥ 区分**：`useEffect` 本身 + "重画之后执行" + "看依赖变化"是 **React 特有**；A 是普通箭头函数、B 是普通数组（`[]`、`[count]` 都是数组字面量，和练习 01 学的没区别）。

**⑦ 三种写法现象对照**

| 写法 | 何时执行 | 打样里的现象 |
|------|---------|-------------|
| `useEffect(fn)` | 每次渲染后 | 零件 1：点几次就几条 |
| `useEffect(fn, [])` | 只在首次挂载后 | 零件 2：点多少次都不再出现 |
| `useEffect(fn, [count])` | 首次 + `count` 变化时 | 零件 3：打字不打印，点按钮才打印 |

## 3. 箭头函数 `() => {}` 是**普通 JS**，不是 React

- **读法**："一个函数——进去是空括号（不收参数），出来是 `{}` 里的代码。"
- 三种身影：
  1. `() => prev + 1` —— 箭头右边是**表达式** → **隐式返回**（不用写 return）
  2. `() => { 语句; return x }` —— 箭头右边是 `{}` → 这是**函数体**，要 `return` 才有返回值
  3. `(e) => ...` —— 收一个参数
- **他问的"useEffect 箭头指向的那个 `{}` 包裹的函数，这个叫什么？"**
  → 它叫 **回调函数（callback function）**：**交给别人、等别人在合适的时机替我调用**的函数。
  - 交给 `useEffect` 的 → 叫"副作用函数 / effect 回调"
  - 交给 `setInterval` 的 → 叫"定时器回调"
  - 交给 `onClick` 的 → 叫"事件处理函数"
  - 它们**共同点**：你写好了不自己调，**交给 API 去调**。这就是"回调"两个字的意思。

## 4. 清理函数 `return () => {...}` 读法卡 ★（回答他的 Q4）

```jsx
useEffect(() => {          // ← 参数1：setup 函数（A）
  if (!running) return     // ① 提前收工：这次不装定时器，A 到此结束
  const timer = setInterval(...)
  return () => {           // ② A 的最后一行：交出一张"善后说明书"
    clearInterval(timer)
  }
}, [running])
```

**⑤ 读法**："A **return 了一个新函数**——不是执行它，是**交给 React 保管**。"
**类比**：装定时器时，你顺手交给 React 一张**善后说明书**；React 拿着站旁边，**到该拆的时候才照做**。
什么时候"该拆"？只有两种：① **依赖（`running`）变了**，重装前先拆旧的 ② **组件被移除**时。

**他的 Q4：为什么"拆掉 timer"没有被执行？一个函数里有 2 个 `return`，它们和 `if` 是什么关系？**
> **关键澄清：那两个 `return` 不属于同一个函数。**
> - `if (!running) return` → 结束的是**参数 1 这个函数这次执行**（提前返回，后面全不跑）→ 返回 `undefined` = "没有说明书"
> - `return () => {...}` → 也是**参数 1 这个函数**的返回语句，返回的是**一个函数**（说明书）
>
> 所以顺序是这样的：
> | 情况 | 走的路 | 结果 |
> |------|--------|------|
> | `running === false`（点"暂停"后） | `if` 命中 → 提前 return | 返回 undefined，**不装**定时器 |
> | `running === true`（点"开始"后） | 跳过 `if` → 装定时器 → 走到最后 return 说明书 | 返回清理函数，**交给 React 存着** |
>
> "拆掉 timer" 没被执行，是因为**现在还不该拆**——把 `running` 从 true 改成 false 的那一刻（或者组件被卸载时），React 才会拿出说明书照着执行。所以你看到的是"装上 → 拆掉"成对出现。

**⑦ 如果清理函数永远不执行会怎样？** 定时器会一直活着：`setSeconds` 还在每秒调用、Closure 里的东西不会被回收 → 内存/性能泄漏，React 会警告你别在已卸载组件上 setState。这就是"副作用要善后"的原因。

## 5. `setX(函数)` 函数式更新 ★（正好接他 TodoApp 的问题）

```jsx
setSeconds((prev) => prev + 1)
//         └─ 参数：上一次的值 ─┘  └─ 返回值 = 新状态 ─┘
```

| 格 | 内容 |
|----|------|
| ② 括号里 | **两种都行**：`setSeconds(5)`（直接给新值）或 `setSeconds(函数)`（给一个"拿旧值算新值"的函数） |
| ⑤ 读法 | "setSeconds：（上一次的秒数）=> 上一次 + 1" |
| ⑥ 区分 | React 特有：setter **允许**收函数，并自动把"上一次的值"喂进去 |
| ⑦ 为什么要用 | **闭包旧值陷阱**：定时器/effect 里看到的 `seconds` 永远是**它出生那一轮**的值（比如 0）。用 `prev =>` 才能拿到最新值——两秒后就是 2，不会是 0+1=1 永远不动 |

> 🔎 **你其实撞见了这个现象**：你的零件 2 里 `useEffect(() => { console.log(..., count) }, [])` 打印的 `count`，
> 无论你点几次 `+1`，**永远是 0**（oxlint 也提示了 `missing dependency: 'count'`）。
> 这不是 bug，是"闭包记住了出生时看到的 count"。→ 这正是"函数式更新"存在的理由。

## 6. `setTodos` 的两种写法对照（回答他 TodoApp 第 18 行）

他写的是：
```jsx
// ❌ 不能这样写
setTodos((prev) => ({ ...prev, { id: Date.now(), text: input, done: false } }))
```

**两个错，都在"括号形状"上：**

| 错误 | 说明 |
|------|------|
| ① `{ ...prev }` | `prev` 是**数组**！把数组摊进 `{}` 会得到 `{0: {...}, 1: {...}, 2: {...}}` —— 一个**对象**，不是数组。于是它**没有顺序、没有 length**，`todos.map` 立刻崩 |
| ② `{ ...prev, { id: ... } }` | 对象字面量里每一项必须是 **`键: 值`**。光秃秃一个 `{...}` 是**语法错误**（数组才允许"只有值"） |

**✅ 正确写法**
```jsx
setTodos((prev) => [...prev, { id: Date.now(), text: input, done: false }])
```

**口诀：中括号 `[]` 造数组，大括号 `{}` 造对象——括号形状要跟"我要造什么"一致。**

顺带解释那个（在正确写法里不需要的）圆括号：
```jsx
(prev) => ({ ...prev, done: true })   // ← 圆括号是为了"直接返回一个对象"
(prev) => { ...prev, done: true }     // ← 这样写会被当成函数体 → 语法错误
```
因为箭头右边遇到 `{}` 默认理解成"函数体"，想返回对象就得用 `()` 包起来。**只有"返回对象"才需要这层圆括号。**

**用哪个？** `setTodos([...todos, x])` 和 `setTodos(prev => [...prev, x])` 都合法。区别：
| 写法 | 拿到的旧值 | 适合场景 |
|------|-----------|---------|
| `setTodos([...todos, x])` | 这一轮渲染里的 `todos`（可能"旧"） | 普通点击事件，一次只改一下 |
| `setTodos(prev => [...prev, x])` | **最新**的值，React 现给的 | 连续多次更新、定时器里、effect 里 |

## 7. `onClick={...}` 的两种形态

```jsx
<button onClick={addTodo}>添加</button>              // 交【函数本身】（不加括号 = 不调用）
<button onClick={() => setCount(count + 1)}>+1</button>  // 交【一个小包装函数】，点击时它才调用
```

| ⑤ 读法 | |
|--------|--|
| `onClick={fn}` | "点击发生时，React 替我执行 `fn`"（React 还会塞一个事件对象进去，不接就忽略） |
| `onClick={() => ...}` | "点击发生时，执行我这个临时小函数"（**故意包一层，是为了"别现在就跑"**） |

- 为什么 `onClick={setCount(count+1)}` 不对？因为它**渲染时立刻就执行了**（`()` 就是调用），页面会死循环报警告。
- ⑥ **React 特有**：`onClick` 小驼峰写法、直接传函数；**普通 JS** 是 `btn.addEventListener('click', fn)`。

## 8. `onChange={(e) => setText(e.target.value)}` 逐段读法 ★（他点名要的）

| 片段 | 读法 |
|------|------|
| `onChange` | "当内容改变时"（React 的事件名；**每敲一个字符都会触发一次**） |
| `{ ... }` | "这里**回到 JS 世界**算一下"（JSX 里的大括号，和 `{count}` 一样） |
| `(e) => ...` | "收到一个参数 `e`，然后……"。`e` 是 **事件对象**——**React 替你塞进去的**；名字随便叫（`e` / `event` / `ev`），`e` 是惯例 |
| `e.target` | "触发这次事件的那个元素"（就是**这个输入框**自己） |
| `.value` | "它当前的内容"（**属性**，无括号——手册§0 的口诀） |
| 整句 | "**这个输入框内容一变，就把元素当前的内容写进 `text` 状态里**" |
| ⑥ 区分 | `e.target.value` 里 `target`/`value` 是原生 DOM 概念（练习 02~05 用过）；React 只是把事件统一成了 `onChange` 这种小驼峰名字 |

**⚠️ 必须成对**：`value={text}`（显示什么）+ `onChange={...}`（用户改了怎么存）——这就是第 4 课的**受控输入**。
少了 `onChange`，输入框会变成"只读"（React 警告你 controlled → read-only）。

## 9. `{}` 在 JSX 里的三种身份（他 confusion 的根源）

| 场合 | 例 | 含义 |
|------|----|------|
| 在 JSX 标签里 | `<div className={x}>`、`{count}` | **"回到 JS 算一下"** |
| 在函数/if 后面 | `() => {}`、`if (x) {}` | **函数体 / 代码块** |
| 对象字面量 | `{ key: value }` | **一个对象** |

**判断窍门**：先问"我在 JSX 里，还是在 JS 里？"——在 JSX 里出现的 `{}` 是"回到 JS"；在 JS 里出现的 `{}` 看它前面是不是 `=>` 或 `if`。
（`{...obj}` 展开对象 = `{}` 身份③；`[...arr]` 展开数组 = `[]`。这张卡第 6 节讲的就是这个。）

## 10. 名词速查（**第一次出现就解释**——我答应的事）

| 名词 | 人话 |
|------|------|
| 回调函数 callback | 交给别人、等别人在合适时机调用的函数 |
| 副作用 side effect | 渲染之外的动作（联网 / 定时器 / 读写 localStorage） |
| 依赖数组 deps | `useEffect` 第二个参数——"我盯着谁" |
| 清理函数 cleanup | effect 交出来的"善后说明书" |
| 受控输入 | `value` + `onChange` 成对，React 掌握输入框内容 |
| 事件对象 event (`e`) | React 塞给事件处理函数的"这次事件的说明书"（`e.target`、`e.target.value`） |
| 函数式更新 | `setX(prev => ...)`，用最新值算新值 |
| 闭包旧值 | effect/定时器里的变量永远是"出生那一轮"的值 |
| 提前返回 early return | `if (...) return`，函数就地结束 |
